# isbn_cleanup

Fixes malformed **ISBN publisher prefix (P3035)** statements on Wikidata. P3035
must hold *only* an ISBN registrant prefix — `978-<group>-<registrant>`, with no
publication element and no check digit. A survey of every P3035 value (~8,700
statements) turned up ~74 that violate the format constraint. The bot splits
them into safe auto-fixes (~52) and a review queue (~22):

| Outcome | ~n | What it is | Bot action |
|---|---|---|---|
| **move** | 51 | A full, valid ISBN pasted into P3035 on a book/work item (e.g. `9780008568207` on *The Beast and the Bethany*) | Add **P212** with canonical hyphenation, then remove the P3035 — a *move*, so the ISBN is preserved |
| **fixprefix** | ~1 | A correct registrant prefix whose only defect is non-ASCII dash characters (e.g. `978‐0‐9747077` with U+2010 hyphens, Roberts & Company) | Normalise the dashes to ASCII **in place**; value stays in P3035 |
| **review** | ~22 | Everything else: a valid ISBN on a **person / publisher / organisation** (library, museum, even a restaurant — where P212 would be wrong); a truncated prefix on a real publisher (`978-5`, `608`); two ISBNs in one field; `ISBN : …` literal text; or an unusual type (scholarly article, comic series) where the ISBN itself is suspect | **Review only**, logged to `output/review.txt` — touch nothing |

All ISBN values are dash-normalised (U+2010–2015, minus sign, fullwidth, …) to
ASCII before classification, so a full ISBN entered with fancy hyphens is
salvaged into a **move** instead of being dumped to review.

Only the **move** and **fixprefix** cases are automated. A value is moved only when
`python-stdnum` confirms it is a valid ISBN (check digit included) **and** the
target item's every `P31` is a bibliographic type (book, written/literary work,
publication, edition, …) — or it has no `P31` at all. Any publisher, person, or
other-typed item goes to `output/review.txt` untouched, because adding P212
there would itself be wrong. See [`../../notes/isbn_bot.md`](../../notes/isbn_bot.md)
for the wider ISBN-bot design this is the first slice of.

## Run

```bash
# from the repo root, with PYTHONPATH=projects (VS Code sets this via .env)
python projects/isbn_cleanup/isbn_cleanup.py               # dry run, whole list
python projects/isbn_cleanup/isbn_cleanup.py --limit 5     # dry run, 5 items
python projects/isbn_cleanup/isbn_cleanup.py --qid Q123    # one item, even if done
python projects/isbn_cleanup/isbn_cleanup.py --save        # really edit
python projects/isbn_cleanup/isbn_cleanup.py --fetch-items # rebuild input/items.tsv (QLever)
python projects/isbn_cleanup/isbn_cleanup.py --recheck-review        # re-run review.txt QIDs (dry)
python projects/isbn_cleanup/isbn_cleanup.py --recheck-review --save # ...and rebuild review.txt
```

`--recheck-review` force-reprocesses every QID currently in `output/review.txt`
(handy after the classifier is improved — e.g. new dash handling or an added
bibliographic type). With `--save` it first truncates `review.txt`, so the file
is rebuilt to contain only what is *still* unresolved; items that now auto-fix
drop out.

Input: `input/items.tsv` (`QID<TAB>value`, generated by `--fetch-items`). The
discovery query asks QLever for every P3035 value that fails the prefix format;
processing re-reads each item live and re-classifies, so a stale input row that
has since been fixed is simply skipped. A dry run makes no edits and records
nothing in `output/`, so it never blocks a later `--save`; it prints the
proposed `move`/`drop`/`REVIEW` lines.

Each run prints `editgroup=<id>`; every edit summary links to
<https://editgroups.toolforge.org> so the batch can be reviewed/reverted there.

## P3035 back-fill (separate tool)

`backfill_p3035.py` *adds* P3035 to publisher items that lack it, from
`data/p3035_backfill_candidates.tsv` (built from the group-0/1 Wikipedia
ISBN-publisher-code lists → QID → filtered; see
[`../../notes/isbn_bot.md`](../../notes/isbn_bot.md)). This is Layer-2
enrichment, distinct from the P3035 *cleanup* above. By default it processes only
the vetted set (`safe_batch=yes` and `registry!=unchecked`, currently **123**
rows), adds each `list_prefix` on its `qid` idempotently, and never touches
existing P3035 statements. State lives in `output/backfill_{done,failed}.txt`.

```bash
python projects/isbn_cleanup/backfill_p3035.py             # dry run, vetted set
python projects/isbn_cleanup/backfill_p3035.py --limit 5   # dry run, 5 items
python projects/isbn_cleanup/backfill_p3035.py --save      # really edit
python projects/isbn_cleanup/backfill_p3035.py --all       # include unvetted rows (careful)
```

## ISBN formatter (P212/P957)

`format_isbn.py` fixes wrongly-hyphenated **ISBN-13 (P212)** / **ISBN-10 (P957)**
*main statements* — the "the `-` is wrong" constraint errors. It reformats to
`python-stdnum`'s canonical hyphenation, but only when the stored value **fails**
the live format-constraint regex **and** stdnum's canonical **passes** it **and**
the number is a valid ISBN. That guard is the whole point: most values stdnum
would touch already satisfy the constraint (churn) or fall in a range where
stdnum lags Wikidata (drift) — the guard cuts ~3,600 stdnum "differences" down to
**~94 genuine fixes** (mostly 979-8 codes the existing hyphenation bot skips).
Invalid ISBNs (bad check digit) are logged to `output/format_review.txt`, never
reformatted. Discovery is live each run (fetches the regex, asks QLever via
`!REGEX`), so new violations are picked up automatically. Only main statements;
P212/P957 as qualifiers/references is a possible follow-up.

```bash
python projects/isbn_cleanup/format_isbn.py             # dry run, whole worklist
python projects/isbn_cleanup/format_isbn.py --limit 5   # dry run, 5 items
python projects/isbn_cleanup/format_isbn.py --qid Q123  # one item, even if done
python projects/isbn_cleanup/format_isbn.py --save      # really edit
```

## Misfiled-value fixer (P212/P957 violations)

`fix_isbn_violations.py` handles the three *deterministic* classes of P212/P957
format-constraint violations — the ones fixable without judgement, each moving
data to the right place rather than deleting it:

| Class | ~n | Action |
|---|---|---|
| **pipe** | 22 | `A\|B` (two ISBNs in one value, e.g. a thesis's print+PDF) → split into two P212 statements, each canonical. Only when **both** halves are valid ISBNs. |
| **ISMN** | 10 | `979-0-…` (music, not ISBN) → move to **P1208 (ISMN)**, in the fixed `979-0-DDDD-DDDD-D` grouping P1208's strict format constraint requires (not stdnum's variable grouping). |
| **ASIN** | 8 | `B0…` Amazon codes (sometimes with a bogus `978-` prefix) → move to **P5749 (ASIN)**. Requires a `B0` prefix, so ISBN-10s ending in `X` are *not* mistaken for ASINs. |

Each move **copies the original claim** (`claim.copy()`), so its references and
qualifiers are carried to the new statement(s) rather than lost. When an ASIN
move leaves the item with **no ISBN at all**, its QID is written to
`output/asin_no_isbn_review.txt` (and printed): a human should open the Amazon
page and either add the real ISBN (KDP paperbacks usually have a 979-8) or, if
it's Kindle-only, model it as `distribution format (P437) = Amazon Kindle` and
leave P212 off — no `novalue`/qualifier needed. Everything else
(invalid check digit, EAN/transposed prefix, plain mis-hyphenation, range drift)
is left for the formatter (Maxlath/DeltaBot) or human review. Live discovery each run; **main statements only** (qualifier/
reference violations are a separate, larger set — see the memo). Note: splitting
a pipe into two P212 trades a format violation for a *distinct-value* soft
warning (no way to tell which ISBN is which format) — acceptable, but visible.

```bash
python projects/isbn_cleanup/fix_isbn_violations.py            # dry run
python projects/isbn_cleanup/fix_isbn_violations.py --limit 5  # dry run, 5 items
python projects/isbn_cleanup/fix_isbn_violations.py --qid Q123 # one item
python projects/isbn_cleanup/fix_isbn_violations.py --save     # really edit
```

## Mark self-published (`mark_selfpublished.py`)

Enrichment, not cleanup: books entered with **publisher (P123) = Amazon (Q3884)**
are almost always **self-published** (someone put "Amazon" where the publisher
belongs). Since a self-published book's publisher *is* the author, the bot removes
the Amazon value and sets **`P123 = the author`** qualified **`object of statement
has role (P3831) = self-publishing (Q1568650)`** — a real person as publisher plus
a self-pub role marker (the form used on Q113134471). That's the version least
likely to be disputed: `P123 = self-publishing (Q1568650)` *directly* is the
~1,600-item majority but a respected editor argues it's an activity, not a
publisher entity (see Property_talk:P123).

Only `P123 = Amazon` on a **bibliographic** P31 is considered (of ~54 such items,
7 are non-books — Kindle Store, the Kindle app, AWS blogs — filtered out by the
discovery query). Six guards send items to `output/selfpub_review.txt` untouched:

- **has sitelinks** — a book with a Wikipedia article is notable; publisher=Amazon
  there is a data artifact, not a self-pub tell (e.g. Q31431887, Q42201914);
- **`P123=Amazon` is referenced** — a sourced publisher value is deliberate, not a
  careless self-pub entry (e.g. Q7100825, whose sitelink was removed);
- **non-979-8 ISBN** — a country-registered ISBN can mean a *real* publisher
  edition where publisher=author would be wrong (e.g. Q64666984, a poem with
  Moroccan/Lebanese/Syrian ISBNs);
- **a non-Amazon publisher already present** — it has a real publisher;
- **no single author item (P50)** — nothing to set as publisher;
- **author died before publication** — a posthumous reprint (a public-domain
  repackager self-published it, not the author), so publisher=author is wrong
  (e.g. Q133859590, a 2024 KDP reprint of Duro Ladipo, d. 1978; or a Kindle
  reprint of H. G. Wells).

So ~30 auto-mark, the rest to review. Broader signals (979-8 ISBN, ASIN, no
publisher) are a separate future pass.

```bash
python projects/isbn_cleanup/mark_selfpublished.py             # dry run
python projects/isbn_cleanup/mark_selfpublished.py --limit 5   # dry run, 5 items
python projects/isbn_cleanup/mark_selfpublished.py --qid Q123  # one item
python projects/isbn_cleanup/mark_selfpublished.py --save      # really edit
```

## Create a book (`make_book.py`)

Creation, not cleanup: turns pasted **Google Books** or **publisher-page** metadata
into a **work** plus **one edition (P31=Q3331189)**, linked `P629`/`P747`. The work's
type is confirmable and defaults smartly: **edited volume (Q1711593)** for an editor-only
book (92% of those carry P98), else **written work (Q47461344)**. You paste the blob (`--file` or interactively, ending with a line
`.`), the tool parses it and you confirm every field, then it creates both items in
one editgroups batch. Dry run by default.

Field split follows the [book data model](../../notes/isbn_bot.md): title/subtitle
(P1476/P1680), language (P407), authors (P50), editors (P98) and subjects (P921) go on
the **work** (P50 and P98 are work-level properties per WikiProject Books, so an edited
volume's editors land on the work too, not only the edition); all publication facts —
publisher (P123), place (P291), date (P577), ISBN
(P212/P957, validated + hyphenated via `python-stdnum`), pages (P1104), edition no.
(P393), DOI (P356), editors (P98), format (P437) — go on the **edition**. It parses
both the Dutch Google labels (`Titel/Redacteurs/Uitgever/ISBN/Lengte`) and the glued
publisher labels (`Edited By…`, `First Published…`, `Pub. Location…`).

At each prompt a parsed value is shown in `[brackets]`: **Enter keeps it**, typing
replaces it, and a single **`-` clears** an optional field to none (Enter can't blank
a pre-filled field — it re-accepts the default).

Contributors are given as names or QIDs (["author can be name or qid"]): with a QID →
P50/P98 item; a bare author name → **P2093** (author name string); a bare editor name
→ **P98 = somevalue + object named as (P1932)**. Publisher without a QID → **P123 =
somevalue + P1932** likewise. Place/subject/series need a QID (name shown as a hint).

```bash
python projects/isbn_cleanup/make_book.py --file book.txt          # dry run
python projects/isbn_cleanup/make_book.py --file book.txt --save   # really create
python projects/isbn_cleanup/make_book.py                          # paste, end with "."
```

## Progress tracking

No database. State lives in text files under `output/` (gitignored), written
only by `--save` runs:

- `output/done.txt` — `QID<TAB>changed|no-change[, review (Nx)]`; skipped on later runs.
- `output/failed.txt` — `QID<TAB>error message`; also skipped. Rerun with `--qid` after fixing the cause.
- `output/review.txt` — `QID<TAB>value<TAB>reason`; the PUBLISHER/OTHER cases left for manual handling.

## Toolforge deployment

Same recipe as clean_google (no database, no API keys):

```bash
ssh login.toolforge.org
become <toolname>
git clone <repo-url> $HOME/wikidata               # or: git -C $HOME/wikidata pull

# build the venv INSIDE a job so it matches the runtime image
toolforge jobs run venv --image python3.11 --wait \
  --command "python3 -m venv ~/venv && ~/venv/bin/pip install -r ~/wikidata/projects/isbn_cleanup/requirements.txt"

# regenerate the work list, then dry-run a few and inspect the .out
toolforge jobs run isbn --image python3.11 --wait \
  --command "bash $HOME/wikidata/projects/isbn_cleanup/toolforge_run.sh --fetch-items"
toolforge jobs run isbn --image python3.11 --wait \
  --command "bash $HOME/wikidata/projects/isbn_cleanup/toolforge_run.sh --limit 5"

# run for real
toolforge jobs run isbn --image python3.11 --wait \
  --command "bash $HOME/wikidata/projects/isbn_cleanup/toolforge_run.sh --save"
```

Gotchas (learned on remove_import_ref / clean_google): the venv only works
inside a job (matching image), never on the bastion; invoke the launcher via
`bash` (the Windows-committed `.sh` lacks `+x`); the launcher sets
`PYTHONUNBUFFERED=1` so the job's `.out` updates live.
